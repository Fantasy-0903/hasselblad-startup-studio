# USB连接故障与传输核验

## 0.1.2 连续传输与 macOS 生命周期修正

2026-10-11，第一代 X2D 100C 4.2.0。
用户实际 0.1.1 日志中，第137次请求在读取首次原厂库备份时出现 LIBUSB_ERROR_IO。
该流程在首次备份读完之前没有修改相机文件；实机核对原库、原配置和原键一致，没有该次安装的自有文件。
目前不能仅据日志把这次 I/O 的唯一原因判定为休眠或硬件故障。

16384字节一块的工厂通道读取需要一百多次请求；图片上传的百余字符分块也会产生大量请求。
0.1.2 使用工厂通道执行控制与哈希核验，内置 ADB 只负责大文件 pull/push。
ADB shell 与工厂通道的实际权限不同，不能把全部命令改成 ADB shell；实机暂存目录创建失败已暴露这一边界。
ADB 写入 /tmp 被拒绝，现使用带归属标记和恢复记录的 /blackbox/.x2d-l3- 随机目录。
恢复同时兼容旧 /tmp 记录；不按通配符删除其他项目文件。

只有文件传输需要时才启用运行时 ADB；选择唯一物理 USB X2D，拒绝无线、离线和其他机型。
切换后重新核验机型、原厂配置指纹和 USB 生效状态；不写 persist 属性、产品身份或原厂显示键。
结束时经工厂通道恢复本次操作开始前的 USB 配置，并等待配置和状态两项读回一致。
启动不自动连接；单纯连接普通原厂相机不启用 ADB。

实机 App 线程采样还确认：USB 重新枚举期间，libusb_exit 的 darwin_exit 等待热插拔线程，
热插拔线程的 darwin_devices_detached 同时等待锁，界面停在关闭上下文。
现在整进程只初始化一个 libusb 上下文，逐会话释放接口和设备句柄；退出进程由系统释放上下文。
不在重连轮询中反复初始化／销毁上下文。替身验证同时检查初始化次数与每会话接口释放。

同一 ManagedCameraLink 的真实传输测试通过：三次 2051168 字节原库完整读取、三次最大
1024×768 灰度资源 push/pull 逐字节一致，整体13秒；原厂快照一致，自有暂存清理，USB 原配置恢复。
该结果属于真实设备传输验收，不替代 App 按钮、冷启动或原厂大地机验收。

同日10:46–10:47直接操作0.1.2发布构建原生窗口：连接约2秒，安装640×480灰度测试图约23秒，
恢复约22秒；两次USB恢复均完成，按钮恢复可操作状态，无关闭上下文卡住。随后原生“重新检测”再次通过。
恢复后独立只读核对原库、原配置、原键、修改时间、显示服务／只读挂载、USB原状态和自有目录清理通过。
此为普通机的完整App按钮验收；本版冷启动视觉和原厂大地机仍未验收。

右侧日志只显示连接、备份、传输、安装／恢复及明确失败原因；USB逐请求统计保存在本地私有诊断文件。
没有复制／删除日志按钮；不记录原命令、图片内容或序列号。

## 代码缺陷与修正

对照本地一键工具包0.4.17的USB工厂通道纯协议代码：
VID2756／PID0009、接口3／alt0、OUT04／IN85、257字节请求、command65、CRC-XMODEM与cookie。
新App请求字节与工具包纯构建函数一致；工具包MAX_BULK_READ为1024，新App旧版为4096。

旧版对LIBUSB_ERROR_TIMEOUT立即continue，忽略transferred中的已收字节。
若相机完成一个1024字节填充回包、主机继续等待更大的读取，收到的数据可能伴随超时返回；
旧逻辑会丢掉有效通知和最终回复。该丢弃是静态确认的代码缺陷，本地替身已覆盖对应路径。

0.1.1统一1024字节读取；超时同时有数据时先解析；CRC错误改成逐字节重同步，避免假头吞掉有效帧。
严格匹配command65与cookie，必须取得成功的最终回复；通知不等于完成。
记录初始化、枚举、接口、端点、发送、读取、相机状态等失败阶段，保留libusb名称及数字错误码。
统计请求长度、收包数／字节数、CRC异常、其他请求、填充、超时带数据及耗时。
大文件每次最多读取16384字节，再核对每块长度；避免原厂库整体base64输出超过单次等待时间。

原生右侧日志包括这些事件与操作阶段。日志不输出命令原文、原厂配置内容、序列号、文件原文或上传数据。
固定原厂版本检测与恢复约束继续有效；绘图适配层、首次备份协议和原厂键的写入边界没有变化。

## 本地证据

USBTransportTests.c链接实际USBBridge.c及本地libusb替身，不链接真实libusb。
check_usb_transport.py默认使用本模块固定合成请求样本；显式传入可选--reference时才额外提取两个纯请求构建函数及数值常量，不导入工具包运行入口。

17项传输检查：1024填充包、超时带数据、分段头／帧、CRC假头重同步、异请求过滤、
缺最终回复、断开、非零执行状态、短写、写／读停滞、CRC损坏、输出上限、无相机、多相机、接口占用和端点缺失。
C检查启用AddressSanitizer与UndefinedBehaviorSanitizer。

11项Swift/C集成检查使用同一实际USBLink及传输源码：正确响应、五种回包路径、错误阶段透传、
枚举／接口／端点错误、回调上下文与会话关闭日志。未使用真实USB驱动。
32项原生／桌面文件系统检查另覆盖大文件拼接、短块拒绝、大小拒绝、日志阶段归类及原有安装／恢复。
原有29项ARM64证据仍对应同一绘图适配层；传输修正没有改变机内绘图代码。

## 0.1.1 当时的 ADB与实机边界

已参考一键工具包的USB与ADB职责拆分。当前App的检查与部署使用工厂USB接口，
没有启用ADB、启动ADB服务、切换USB配置或新增常驻通道。日志准确标记当前通道。
不能借ADB绕过无设备、接口占用、机型／原厂库不符等检查。

实际相机的连接、长文件传输、服务恢复、断开与冷启动仍需用户实测；本地替身不证明驱动／相机实际行为。
本地保存和打包，未提交、推送或发布。
